## Evidence and required answers

For each answer, cite source paths, exact excerpts or authentic evidence artifacts and explain what was actually checked. State pending work rather than filling in presumed success. Evidence references must be local repository-relative paths with exact raw-file SHA-256 values, without private user records.

1. Schema: inspect catalog/publication-profile diagnostics and identity, package contents and versions.
2. Safety: inspect each instruction, permission and privacy boundary; identify consequential decisions and qualified domain-review needs. Static validation is not security verification.
3. Originality: inspect provenance, license/third-party rights, exact-copy indicators and related-task overlap. Do not certify external originality from local fingerprints.
4. Usefulness: name the user, task, input assumptions and actionable expected output. Do not invent usage or success statistics.
5. Completeness: read workflow, both examples, limitations, supporting files and edge/failure cases. Identify unsupported assumptions.
6. Compatibility: separate documented installation and declared compatibility from completed tests. Record actual platform/version evidence or explicitly state untested.
7. Evaluation: distinguish authored fixture expectations from executed output, baseline comparisons, objective assertions and genuine agent runs. Cite only completed reports actually inspected.
8. Limitations: state unresolved findings, untested behaviors, professional-review requirements and permitted launch scope. Human approval alone does not create performance, security or compatibility verification.

## Final exact-content check

Confirm the package digest still matches the complete reviewed contents, including final metadata status and platform evidence. Record the generated report hash, exact evidence references and the manually completed record hash. Run the integrity check; it must not write approval. Use the existing ledger and genuine GitHub review/merge gate only after the actual maintainer review. Never substitute automation, an assistant-generated identity or a shortlist recommendation for approval.
