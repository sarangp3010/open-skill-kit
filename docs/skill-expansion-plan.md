# Universal marketplace expansion plan

This batch proposes **50 new skills**, of which **19 are authored drafts** and **31 are proposals only**. The proposal list is planning documentation, not a second catalog or evidence of availability. Proposed entries have no placeholder packages and are not indexed. Every authored package has a focused workflow, two fictional input/output pairs, six declared behavior-review cases and two deterministic offline replay scenarios. These are authoring/validation artifacts, not completed assistant tests.

## Scope and taxonomy

The registry defines 20 broad sectors. Existing collection IDs and URLs are preserved, with canonical browsing aliases for four overlapping legacy names. See [taxonomy](sector-taxonomy.md) for membership, scope boundaries, planned collections and extension rules. Skills remain portable at skills/{collection}/{skill}/SKILL.md. Their folder identity determines collection membership; React contains no authored skill arrays.

## Review and validation limits

All 19 packages remain draft with testedPlatforms empty and lastVerified null. No actual agent, clinical assessment, financial authorization, legal interpretation, engineering approval, environmental certification or event-safety clearance is represented. Domain professionals must review consequential workflows before reliance. Their records are synthetic; no real personal, patient, payment or confidential data was used.

The offline suites under evaluations/scenarios use the Phase 4 runner with identical authored baseline and assisted observations. Successful replay confirms the assertions, file captures and reporting pipeline only; it cannot measure skill effectiveness. Fresh reports stay ignored. No new real-agent result or platform-test record is imported into the marketplace.

The unit tests verify portable-package validation and ZIP preservation, identity preservation, taxonomy counts/aliases/planned status, schema safety, fixture reproduction and selected illustrative arithmetic. Declared behavior cases remain review specifications, not executed model behavior. See [evaluation framework](skill-evaluation.md) and the latest [implementation status](IMPLEMENTATION_STATUS.md) for actual command results.
