# Release authorization worksheet — unsigned and not authorized

No item is selected, no reviewer is named and no signature/date is supplied. The [manifest](release-manifest.unsigned.json) is a source/artifact observation plus blank planning fields; it is not accepted by the skill approval schema or publication ledger and has no importer.

## Before an actual authorization

- [ ] Confirm rights/provenance for source, all candidate packages and any adapted material. Resolve or explicitly bound each notice case with authentic evidence; no silent exception acceptance.
- [ ] Complete approve/reject/defer choices for each exact candidate hash after reading all files, concerns and evidence limitations. Use an actual authorized maintainer; obtain domain review where needed.
- [ ] Finish candidate edits/promotion first, regenerate hashes/reports and obtain renewed exact-content review. Final approval requires the existing real review record, genuine current-head GitHub approval and authorized merge. Editing this worksheet cannot supply those.
- [ ] Verify main protection, required checks, trusted reviewer permissions, fork token/secret restrictions and an operational confidential reporting route. Record actual settings and who checked them, not assumed values.
- [ ] Observe successful Ubuntu validate/audit and public-only Windows/macOS portability runs for the exact final commit; skipped jobs are not passes or native evidence.
- [ ] Confirm repository visibility/plan and available free controls. Private/free limitations must remain blockers; never buy a feature or expose drafts automatically.
- [ ] Rebuild/revalidate the final reviewed candidate; inspect license notices, published catalog, every ZIP/npm file and actual tarball/web hashes. Observed artifacts in this packet are not tied to an attested build commit.
- [ ] Choose final version and verify npm account/package ownership, release notes and any rollback/removal plan. Empty approved distribution remains blocked.
- [ ] Explicitly consider that a public repository/site exposes the source draft library even when /published is empty. A publication status does not provide confidentiality.
